SYNTHETIC MATRIX COMPLETION: DOCUMENTATION
==========================================

Main files
----------

1. synthetic_api.py
   Main Python API for synthetic experiments.
   This is the "gray box": generation, missingness, methods, metrics, plots.

2. synthetic_control_panel.ipynb
   Main notebook-panel for interactive work.
   Recommended entry point if you want to run experiments by hand.

3. synthetic_dashboard.ipynb
   Same notebook content kept for compatibility.

4. matrix_completion_experiments.py
   Older script-based benchmark engine.
   Still useful as a solver backend, but not the main interface for new work.


General idea
------------

The new architecture is stage-based.

Instead of "one huge benchmark command", the synthetic experiment is split into
small steps:

1. Generate a low-rank matrix.
2. Optionally modify its structure.
3. Build a missingness field.
4. Convert that field into an observed mask.
5. Split observed entries into fit / validation / test.
6. Add noise and build the observed matrix.
7. Package everything into a Scenario.
8. Run the chosen methods on that Scenario.
9. Aggregate metrics, build tables and plots.

This makes it easy to:
- change one parameter in a loop;
- inspect intermediate objects;
- compare methods on exactly the same data;
- build plots and tables for the course project.


Recommended workflow
--------------------

If you want to work comfortably:

1. Open synthetic_control_panel.ipynb
2. Edit configs there
3. Materialize one scenario
4. Check the generated matrix and masks visually
5. Run a small set of methods
6. Run a sweep over one parameter
7. Save csv / tex tables

If you want to script everything in Python, import synthetic_api.py directly.


Core objects
------------

The main configuration object is:

    ScenarioConfig

It contains:

    matrix             -> MatrixConfig
    structure          -> StructureConfig
    missingness_field  -> MissingnessFieldConfig
    mask_sampling      -> MaskSamplingConfig
    split              -> SplitConfig
    noise              -> NoiseConfig

The main runtime object is:

    Scenario

It stores:

    X_true
    X_structured
    missingness_field
    mask_split
    Y_observed
    metadata


Stage 1. Matrix generation
--------------------------

Function:

    generate_base_matrix(config, rng)

Config:

    MatrixConfig(
        m=60,
        n=60,
        rank=4,
        factor_distribution='gaussian',
        singular_value_profile='linear',
        singular_scale=1.0,
        coherence_mode='incoherent',
        coherence_strength=0.9,
        sparse_additive_fraction=0.0,
        sparse_additive_scale=0.0,
    )

Important parameters:

- m, n
  Matrix size

- rank
  True rank of the generated low-rank matrix

- factor_distribution
  Distribution for factors U and V
  Available now:
    gaussian
    uniform
    rademacher

- singular_value_profile
  Shape of singular values
  Available now:
    linear
    flat
    geometric

- coherence_mode
  Controls how concentrated singular vectors are
  Available now:
    incoherent
    coherent_rows
    coherent_cols
    coherent_both

- coherence_strength
  How strong the concentration is

- sparse_additive_fraction, sparse_additive_scale
  Optional sparse perturbation on top of the low-rank matrix


Stage 2. Structural transform
-----------------------------

Function:

    apply_structure(X, config, rng)

Config:

    StructureConfig(
        mode='none',
        strength=0.0,
        secondary_strength=0.0,
    )

Available structure modes now:

- none
- row_scale
- column_scale
- checkerboard
- additive_block

Use this stage if you want to create a matrix that is still based on low rank,
but also has extra visible structure.


Stage 3. Missingness field
--------------------------

Function:

    build_missingness_field(X, config, rng)

Important idea:

This function does NOT immediately create a boolean mask.
It creates a matrix of scores.

These scores describe which entries are more likely to be missing.
After that, a separate function converts scores into an observed mask.

Config:

    MissingnessFieldConfig(
        mode='random',
        concentration=1.0,
        width=0.15,
        row_index=None,
        col_index=None,
        value_dependence=0.0,
    )

Available missingness field modes now:

- random
  Nearly uniform pattern

- block
  One concentrated block / cluster

- clustered
  Several local clusters

- row_focus
  Missingness concentrated near one row

- column_focus
  Missingness concentrated near one column

- value_based
  Missingness correlated with matrix values

Extra parameter:

- value_dependence
  Adds value-based dependence on top of the main pattern


Stage 4. Observed mask
----------------------

Function:

    sample_observed_mask(missingness_field, config, rng)

Config:

    MaskSamplingConfig(
        observed_fraction=0.35,
        exact_fraction=True,
        threshold=None,
        invert_scores=False,
    )

Important parameters:

- observed_fraction
  Fraction of entries that remain observed

- exact_fraction
  If True, the number of observed entries is forced to be exact

- threshold
  Optional threshold mode if exact_fraction=False

- invert_scores
  Reverses the interpretation of the field

Interpretation:

By default, lower score means "more likely to stay observed".


Stage 5. Split into fit / validation / test
-------------------------------------------

Function:

    split_observed_mask(observed_mask, config, rng)

Config:

    SplitConfig(
        validation_fraction=0.15,
        test_fraction=0.15,
    )

Output:

    MaskSplit(
        observed_mask,
        train_mask,
        fit_mask,
        validation_mask,
        test_mask,
    )

Meaning:

- fit_mask
  Used when you want to train candidate models for selection

- validation_mask
  Used for parameter selection, for example lambda selection

- train_mask
  Union of fit and validation

- test_mask
  Final held-out evaluation mask


Stage 6. Observed matrix with noise
-----------------------------------

Function:

    build_observed_matrix(X_structured, observed_mask, config, rng)

Config:

    NoiseConfig(
        mode='gaussian',
        std=0.0,
        outlier_fraction=0.0,
        outlier_scale=0.0,
    )

What this does:

- keeps only observed entries;
- optionally adds Gaussian noise;
- optionally adds sparse outliers.


Stage 7. Packaging the scenario
-------------------------------

There are two ways.

Option A: full automatic assembly

    scenario = assemble_scenario(config, seed=42)

This is convenient when you trust the whole pipeline and just want a scenario.

Option B: manual stage-by-stage assembly

    rng = make_rng(42)
    X_true = generate_base_matrix(...)
    X_structured = apply_structure(...)
    field = build_missingness_field(...)
    observed_mask = sample_observed_mask(...)
    split = split_observed_mask(...)
    Y_observed = build_observed_matrix(...)
    scenario = package_scenario(...)

This is the recommended mode when you want maximum control.


Methods
-------

Methods are specified as Python objects:

    make_method(name, label=None, **params)

Examples:

    make_method('soft_impute', rank=4, max_iter=80)
    make_method('als', rank=4, max_iter=50, reg=1e-3)
    make_method('rgd', rank=4, max_iter=120, init='spectral')
    make_method('rgd_l2', rank=4, max_iter=120, l2_reg=0.03)
    make_method('compact_rgd', rank=4, max_iter=100)
    make_method(
        'compact_l2_selected',
        rank=4,
        max_iter=90,
        l2_grid=[1e-3, 3e-3, 1e-2, 3e-2],
    )

Available method names now:

- soft_impute
- als
- rgd
- rgd_l2
- rgd_l2_selected
- compact_rgd
- compact_rgd_l2
- compact_l2_selected


Running one experiment
----------------------

If you already have a Scenario:

    result = run_experiment_on_scenario(scenario, methods)

If you only have a config:

    result = run_single_experiment(config, methods, seed=42)

Result type:

    ExperimentResult

Contains:

- scenario
- method_results
- records

records is usually the most convenient object for tables and aggregation.


Minimal example
---------------

from synthetic_api import *

matrix_cfg = MatrixConfig(m=60, n=60, rank=4)
structure_cfg = StructureConfig(mode='none')
missing_cfg = MissingnessFieldConfig(mode='random')
mask_cfg = MaskSamplingConfig(observed_fraction=0.35, exact_fraction=True)
split_cfg = SplitConfig(validation_fraction=0.15, test_fraction=0.15)
noise_cfg = NoiseConfig(mode='gaussian', std=0.02)

config = ScenarioConfig(
    matrix=matrix_cfg,
    structure=structure_cfg,
    missingness_field=missing_cfg,
    mask_sampling=mask_cfg,
    split=split_cfg,
    noise=noise_cfg,
)

scenario = assemble_scenario(config, seed=42)

methods = [
    make_method('soft_impute', rank=4, max_iter=80),
    make_method('rgd', rank=4, max_iter=120, init='spectral'),
    make_method('rgd_l2', rank=4, max_iter=120, init='spectral', l2_reg=0.03),
]

result = run_experiment_on_scenario(scenario, methods)
summary = aggregate_records(result.records, by=['method'])


Parameter sweeps
----------------

The main helper is:

    one_factor_sweep(base_config, parameter_path, values, methods, seeds)

Example: sweep by true rank

    runs = one_factor_sweep(
        base_config=config,
        parameter_path='matrix.rank',
        values=[4, 6, 8, 10],
        methods=methods,
        seeds=[41, 42, 43],
    )

    records = collect_records(runs)
    summary = aggregate_records(records, by=['matrix.rank', 'method'])

Example: sweep by missingness type

    runs = one_factor_sweep(
        base_config=config,
        parameter_path='missingness_field.mode',
        values=['random', 'block', 'clustered', 'row_focus', 'column_focus'],
        methods=methods,
        seeds=[41, 42],
    )

You can also create your own loop with:

    apply_overrides(config, {'matrix.rank': 8})

This is useful when you want more freedom than one_factor_sweep gives you.


Aggregation
-----------

Raw rows:

    result.records

Combining multiple runs:

    records = collect_records(runs)

Aggregation:

    aggregate_records(records, by=[...])

Typical groupings:

- by=['method']
- by=['matrix.rank', 'method']
- by=['missingness_field.mode', 'method']
- by=['matrix.coherence_mode', 'method']

Main aggregate metrics:

- avg_test_rmse
- avg_test_mae
- avg_relative_fro_error
- avg_runtime_sec
- avg_iterations
- avg_train_rmse_observed


Plots
-----

Available helpers:

    plot_matrix(X, ...)
    plot_mask(mask, ...)
    plot_metric(rows, x=..., y=..., hue='method', ...)
    plot_histories(method_results, metric_key='train_objective', ...)

Typical usage:

    plot_matrix(X_true, title='True matrix')
    plot_mask(mask_split.observed_mask, title='Observed mask')

    plot_metric(
        summary,
        x='matrix.rank',
        y='avg_test_rmse',
        hue='method',
        title='RMSE vs rank',
    )

    plot_histories(result.method_results, metric_key='train_objective')


Export
------

CSV:

    write_csv(rows, path)

LaTeX:

    write_latex_table(rows, columns, caption, label, path)

Typical usage:

    write_csv(summary, 'rank_summary.csv')

    write_latex_table(
        rows=summary,
        columns=[
            ('matrix.rank', 'Rank'),
            ('method', 'Method'),
            ('avg_test_rmse', 'Avg. RMSE'),
        ],
        caption='Comparison by rank.',
        label='tab:rank-comparison',
        path='rank_table.tex',
    )


Practical recipes
-----------------

1. Fast sanity check

- m=n=30
- rank=4
- observed_fraction=0.35
- noise std=0.01
- methods: soft_impute, rgd
- small max_iter

2. Rank study

- fix all parameters
- sweep matrix.rank over [4, 6, 8, 10]

3. Missingness study

- fix matrix generation
- sweep missingness_field.mode

4. Coherence study

- fix everything else
- sweep matrix.coherence_mode over
  incoherent, coherent_rows, coherent_cols, coherent_both

5. Regularization study

- compare rgd, rgd_l2, compact_rgd, compact_l2_selected


Which files should be considered "main" now
-------------------------------------------

Use these as the current main interface:

- synthetic_api.py
- synthetic_control_panel.ipynb

Treat these as legacy / older infrastructure:

- synthetic_core.py
- matrix_completion_experiments.py
- matrix_completion_lab.ipynb

You do not need to delete them, but for new experiments it is better to start
from synthetic_api.py and synthetic_control_panel.ipynb.


If something feels too abstract
-------------------------------

The safest workflow is:

1. Open synthetic_control_panel.ipynb
2. Change only one config block
3. Run stage-by-stage materialization
4. Look at plots of matrix and masks
5. Run 2 or 3 methods first
6. Only then start a sweep

That usually prevents long confusing runs and makes it easier to understand
what exactly changed in the experiment.
